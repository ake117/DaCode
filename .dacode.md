# DaCode gate for DaCode

Canonical command (every rig run in this repo goes through this):

```bash
dacode run "<task>" \
  --test-command "${VIRTUAL_ENV:?activate the DaCode venv first}/bin/python -m pytest -q -o addopts=" \
  --test-glob "test_*.py" \
  --llm openrouter --model deepseek/deepseek-v4.1-flash \
  --executor pi --budget 2 --variants 2
```

Rules:

- **The test command must reach a real interpreter.** Trial worktrees are
  checkouts and `.venv` is gitignored, so a relative `.venv/bin/python` runs 0
  tests and every variant fails the gate for the wrong reason. `${VIRTUAL_ENV}`
  works because the executor inherits the caller's environment; if you have not
  activated the venv, pass the absolute path instead.
- **`-o addopts=` is part of the gate.** `pyproject.toml` sets `addopts = "-q"`;
  a second `-q` suppresses the `N passed` summary and the gate reads 0 tests. The
  critic retries with `-o addopts=` when that happens, but passing it up front
  keeps the first probe honest.
- **One module per run.** `dacode/discipline/*`, `dacode/harness/*`,
  `dacode/memory/*`, `dacode/mcp/*`, `dacode/state.py` — a task that spans
  several layers cannot be gated by one test file.
- **Tests are the contract.** Write the failing test first and hand the rig "make
  `tests/<file>.py` pass … do NOT modify the test file". The critic rejects any
  trial that edits, deletes or skips tests.
- **Isolation:** this suite is offline, so `--isolate bwrap` (the default) is safe; add `--isolate-network` only when the *executor* is `pi`. The gate
  never needs the network, and `${VIRTUAL_ENV}` keeps working because the venv is
  re-bound read-only inside the sandbox.
- **Budgets:** 1 for a mechanical edit, 2 for a feature, 3 only for calibration
  work; add `--judge jev` only as a tie-break.
- **Nothing in this repo may require a network, a vault, or another agent.** The
  suite runs offline with `DACODE_RUNLOG=off` and a temporary `DACODE_MEMORY_DB`.

After a PASS, the winner is still a proposal: copy the files out of the printed
worktree, run the suite here, review the diff, then commit.
